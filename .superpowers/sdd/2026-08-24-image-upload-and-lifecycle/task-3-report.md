## Behavior delivered

- Upload inputs are rejected before Storage for an unsupported/invalid file, invalid offer UUID, non-integer or negative position, and alt text outside the trimmed 5–180 character range.
- A single `crypto.randomUUID()` produces a path through `createImagePath`; `File.name` is never used in the object path or metadata.
- Upload order is Storage object first, gallery row second. A failed row insert removes only the path generated by that invocation.
- Both returned and rejected compensation cleanup failures emit only `image_upload_compensation_failed` plus `{ storagePath }`, then preserve the neutral database-write message.
- Gallery list rows are parsed by `offerImageRowSchema`, ordered by `position`, and enriched through the existing administrator signed-URL mapper.
- Hero selection first filters `offer_images` by both `id` and `offer_id`, then changes only `offers.hero_image`; it does not delete a prior image row.
- Delete checks hero and gallery references before row deletion, then repeats both checks immediately before Storage removal. A reference that appears after row deletion silently prevents object cleanup.
- Failed object removal logs `offer_image_cleanup_failed` without raw errors, filenames, or signed URLs. `ImageCleanupPendingError` exposes only `storagePath` as retry state (in addition to standard `Error` fields).
- Retry accepts only generated offer-image path shapes, rechecks every reference, and removes from Storage only when unreferenced.
- Reorder requires an exact, duplicate-free permutation of the offer's complete image ID set. It writes temporary positions `maxPosition + count + index + 1` before final positions `0..n-1`, avoiding the existing unique constraint without RPC or migration.
- A reorder mutation failure refreshes the current database order and throws a neutral repository error.

## Concerns and follow-up

- Reordering remains intentionally non-transactional per the ledger ruling. Concurrent administrators or a mid-sequence database failure can leave temporary positions in the database; the repository refreshes and reports a neutral retryable failure, but it cannot roll back without an RPC/migration.
- Cleanup retry state deliberately contains the private object path. Task 4 must keep it only in component state and must not render it to administrators.
